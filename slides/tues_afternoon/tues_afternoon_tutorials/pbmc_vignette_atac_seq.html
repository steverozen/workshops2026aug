Checkpoint files

ImportantNothing here is recomputed during class

Timed on 2026-07-26, on a 30 GB laptop. This tutorial cannot be run from scratch in a class slot, and it does not fit in 16 GB of RAM:

Step Cost from scratch
CreateChromatinAssay + NucleosomeSignal + TSSEnrichment tens of minutes, and it streams the 2.6 GB fragments file
GeneActivity tens of minutes
FindTransferAnchors / TransferData tens of minutes
FindMarkers(test.use = "wilcox") over ~100k peaks hours without presto
FindMarkers(test.use = "LR") over ~100k peaks hours, one logistic regression per peak

Peak memory during the fragment and GeneActivity steps was about 15 GB, which will not survive on a 16 GB student machine alongside RStudio and a browser.

So every expensive step is checkpointed to .rds in the workshop data directory, and in class each one is loaded, not computed. Loading is seconds and the loaded object is a few GB. The eval: false staging blocks are what produced those checkpoints, run once ahead of the workshop.

Two things must be true before the session, or students will silently fall into the recompute path:

  1. The four pbmc_atac_ck*.rds files are present in the data directory.
  2. presto is installed. Without it FindMarkers falls back to a much slower implementation. remotes::install_github("immunogenomics/presto").

Checkpoints are read from the workshop data directory. If one is missing, the tutorial recomputes it and writes the result to gitignore/ locally rather than to the shared data directory, which students will not have write access to.

Build the Signac object and compute QC metrics

This block builds the Seurat/Signac object from the 10x outputs, keeps standard chromosomes only, attaches Ensembl 98 gene annotations, and computes the nucleosome signal, TSS enrichment, % reads in peaks, and blacklist ratio per cell. The resulting object is cached to ck_qc.

if (file.exists(ck_qc)) {
  pbmc <- readRDS(ck_qc)
  message("Loaded pbmc from ", ck_qc)
} else {
  counts <- Read10X_h5(
    filename = file.path(
      data_dir,
      "10k_pbmc_ATACv2_nextgem_Chromium_Controller_filtered_peak_bc_matrix.h5"
    )
  )

  metadata <- read.csv(
    file = file.path(
      data_dir,
      "10k_pbmc_ATACv2_nextgem_Chromium_Controller_singlecell.csv.gz"
    ),
    header = TRUE,
    row.names = 1
  )

  chrom_assay <- CreateChromatinAssay(
    counts = counts,
    sep = c(":", "-"),
    fragments = file.path(
      data_dir,
      "10k_pbmc_ATACv2_nextgem_Chromium_Controller_fragments.tsv.gz"
    ),
    min.cells = 10,
    min.features = 200
  )

  pbmc <- CreateSeuratObject(
    counts = chrom_assay,
    assay = "peaks",
    meta.data = metadata
  )

  # Keep only standard chromosomes.
  peaks.keep <- seqnames(granges(pbmc)) %in% standardChromosomes(granges(pbmc))
  pbmc <- pbmc[as.vector(peaks.keep), ]

  # Pull Ensembl 98 EnsDb (Homo sapiens) and the ENCODE hg38 blacklist
  # from AnnotationHub. `AH75011` is the accession for the Ensembl 98
  # EnsDb (a SQLite-backed Ensembl annotation database mapped to GRCh38).
  ah <- AnnotationHub()
  ensdb_v98 <- ah[["AH75011"]]
  blacklist_regions <- ah[["AH107305"]] # ENCODE blacklist for hg38

  annotations <- GetGRangesFromEnsDb(ensdb = ensdb_v98)
  seqlevels(annotations) <- paste0("chr", seqlevels(annotations))
  genome(annotations) <- "hg38"
  Annotation(pbmc) <- annotations

  pbmc <- NucleosomeSignal(object = pbmc)
  pbmc <- TSSEnrichment(object = pbmc)
  pbmc$pct_reads_in_peaks <- pbmc$peak_region_fragments / pbmc$passed_filters * 100
  pbmc$blacklist_ratio <- FractionCountsInRegion(
    object = pbmc, assay = "peaks", regions = blacklist_regions
  )

  saveRDS(pbmc, ck_qc)
  message("Saved checkpoint ", ck_qc)
}

if (file.exists(ck_dimred)) {
  pbmc <- readRDS(ck_dimred)

  pbmc <- subset(
    x = pbmc,

Find differentially accessible peaks between cell types

presto greatly accelerates FindMarkers. It comes from GitHub (https://github.com/immunogenomics/presto) and must be installed before the workshop, never during a session. The setup chunk at the top of this document reports whether it is present.

Both differential-accessibility tests below are checkpointed together into ck_markers. They are the single most expensive part of this tutorial: the Wilcoxon test scans roughly 100k peaks, and the logistic-regression test fits one model per peak. In class these load from the .rds.

DefaultAssay(pbmc) <- "peaks"

if (file.exists(ck_markers)) {
  marker_results <- readRDS(ck_markers)
  da_peaks <- marker_results$da_peaks
  lr_da_peaks <- marker_results$lr_da_peaks
  message("Loaded differential accessibility results from ", ck_markers)
} else {
  # wilcox is the default option for test.use. This is the step that needs
  # presto. Without it, expect hours rather than minutes.
  da_peaks <- FindMarkers(
    object = pbmc,
    ident.1 = "CD4 Naive",
    ident.2 = "CD14+ Monocytes",
    test.use = "wilcox",
    min.pct = 0.1
  )

  # Logistic regression with total fragment count as a latent variable. LR
  # fits a model per peak and gets no benefit from presto, so it is restricted
  # to the peaks the Wilcoxon test already flagged. Running it genome-wide
  # takes hours and changes none of the conclusions drawn below.
  lr_features <- head(rownames(da_peaks[order(da_peaks$p_val), ]), 500)
  lr_da_peaks <- FindMarkers(
    object = pbmc,
    ident.1 = "CD4 Naive",
    ident.2 = "CD14+ Monocytes",
    test.use = "LR",
    latent.vars = "nCount_peaks",
    features = lr_features,
    min.pct = 0.1
  )

  saveRDS(
    list(da_peaks = da_peaks, lr_da_peaks = lr_da_peaks),
    file.path(ck_write_dir, "pbmc_atac_ck4_markers.rds")
  )
  message("Saved checkpoint pbmc_atac_ck4_markers.rds")
}
